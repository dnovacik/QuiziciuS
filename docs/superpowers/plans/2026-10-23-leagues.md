# Leagues Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hosts propose, run and close leagues (and Super Leagues); captains join them; league
nights are ticked at launch and scored by placing; one-off teams are offered registration before
the first question.

**Architecture:** A new `leagues` API module owns five tables (migration 0015) through a
`LeaguesRepository`. Standings are computed in a pure `standings.ts` from each finished league
night's final scores (taken from `QuizEngineService.getState`), and frozen into `league_results`
on close. Teams that played a night are upserted as `JOINED` whenever a league is read (no hook in
the engine, so there is no cycle). The web gets a real `/host/leagues` page, a league tick in the
launch dialog, lobby markers, team-page invitations and a registration banner on the phone.

**Tech Stack:** NestJS + Supabase (service role, RLS deny-all), Jest; React + Vite + Tailwind,
Vitest + Testing Library; lucide-react icons; Slovak and English locales.

**Spec:** `docs/superpowers/specs/2026-10-23-leagues-design.md`

## Global Constraints

- Points per place (LEAGUE): `[10, 8, 6, 5, 4, 3, 2, 1]`, then 0. Ties share the better place (1, 1, 3).
- Standings tie-break: more 1st places, then more 2nd, …, then fewer nights, then name (`localeCompare`).
- SUPER leagues: points = sum of raw final scores; only `league_teams` members count.
- Qualification: top 3 per `league_teams.pub_id`; everyone tied at 3rd qualifies.
- Registration from the phone only while the session is `LOBBY` (`409 REGISTRATION_CLOSED`).
- Error codes: `NOT_LEAGUE_HOST` (403), `PUB_NOT_IN_LEAGUE` (400), `LEAGUE_CLOSED` (409),
  `LEAGUE_NOT_FOUND` (404), `NOT_LEAGUE_OWNER` (403), `SUPER_LEAGUE_EXISTS` (409),
  `LEAGUE_NOT_CLOSED` (409), `REGISTRATION_CLOSED` (409), `ALREADY_IN_SESSION` (409).
- Every route has `@RequireRole` (the policy test in `auth/require-role.spec.ts` enforces it).
- Slovak strings first, English alongside; add them with the scratchpad `merge-locales.cjs`.
- Behaviour-focused tests; one commit per task; `pnpm format` before each commit; CI runs
  `pnpm format:check`, `pnpm -r build`, tests.
- Deviation from the spec, decided while planning: the phone's league info comes from the public
  `GET /sessions/:id/display` (which players already load), not the state endpoint; the phone
  registration route is `POST /registered-teams/:id/sessions/:sessionId/claim` with the team token
  in the body, because one request cannot carry two bearer tokens.

## Review Focus

- A registered team that both declined and then played a night → it appears as JOINED with points.
- A score correction (paper score) after a night of a **closed** league → the final table does not change.
- Two linked teams with equal scores on a night → both get the better place's points; the next one skips a place.
- A team whose primary pub is not a league pub plays at the co-host's pub → it qualifies through that pub, not twice.
- A phone claiming a registered team whose name another session team already uses → `409`, the seat keeps working unregistered.
